# ページ全体を閲覧者視点で再編集する

このページについて、個々の文章を直す前に、
ページ全体を1つの体験として確認してください。

今回は「セクションを増やす」「コピーを考える」作業ではありません。

編集者・UIデザイナーの立場で、

- 閲覧者は何を知りたいのか
- どの順番なら理解しやすいか
- 同じ内容を何度説明しているか
- なくても意味が通じる見出しや説明はないか
- スマートフォンで縦に長くなりすぎていないか

を確認し、ページ全体を整理してください。

---

## 最重要方針

情報を追加する前に、削除・統合を検討してください。

現在ある要素をすべて残す必要はありません。

「説明があるから残す」のではなく、

**その情報が閲覧者の理解や次の行動に必要か**

で判断してください。

---

# まず実装せず、ページ全体を監査する

最初はコードを変更しないでください。

現在のページを上から下まで実画面で確認し、

各セクションについて以下を整理してください。

1. このセクションの目的
2. 閲覧者がここで知ること
3. 前後のセクションと内容が重複していないか
4. 削除できる要素
5. 他のセクションへ統合できる要素
6. スマホで縦に長くしている原因
7. 残す場合、もっと簡潔にできるか

---

# セクションには1つの役割だけ持たせる

1つのセクションで同じ内容を、

- 小見出し
- 番号
- 大見出し
- 説明文
- 見るポイント
- 操作の流れ

のように何度も説明しないでください。

例えば、

01 / 写真を整理する
写真を工種別に整理する
工種ごとの分類とファイル名変更を確認できます
見るポイント：整理前後を見比べる
操作の流れ：整理するを押す

のような構造は過剰です。

閲覧者の理解に必要な最小限まで減らしてください。

---

# 原則として避ける構造

以下をテンプレートとして自動的に追加しないでください。

- 01 / ○○ のステップラベル
- eyebrow + 見出し + 説明の3重構造
- 「見るポイント」
- 「このセクションでわかること」
- 「この体験でわかること」
- 「操作の流れ」
- 同じ意味を言い換えただけの補足文
- セクションタイトルのためだけのセクションタイトル
- 大きなCTA直前にもう一度同じ説明をする文章

必要な場合だけ使ってください。

---

# 判断基準

要素を1つ追加または残すたびに、

「これを消したら閲覧者は理解できなくなるか？」

を確認してください。

消しても理解できるなら削除候補です。

---

# 情報の深さを分ける

ページ内の情報量は以下の3段階に分けてください。

## 1. 最初に見る情報

数秒で、

- 何のデモか
- 何ができるか

が分かれば十分です。

説明しすぎないでください。

## 2. 画面を見て理解する情報

画像と短いタイトルを中心にします。

画像を見れば分かることを文章でもう一度詳しく説明しないでください。

## 3. 必要な人だけ読む情報

操作方法、注意事項、利用条件などは、
アコーディオンなどにまとめてください。

最初から長文をすべて表示しないでください。

---

# スマートフォンを基準にする

390px幅でページ全体を確認してください。

1セクションが何画面分も続く場合、

- 本当にその文章が必要か
- 同じことを前ですでに説明していないか
- 詳細を折りたためないか
- 画像だけで伝わらないか

を確認してください。

単純に文字サイズや余白を小さくして解決しないでください。

まず情報量を減らしてください。

---

# 建設デモで目指す構成

今回の建設デモでは、以下程度の構成を基準に検討してください。

## 1. Hero

何のデモか
+
デモを開くCTA

## 2. 3つの画面

セクション見出し：
写真整理から提出後の確認まで

カード1：
写真を送る
+ 画像

カード2：
整理して下書き
+ 画像

カード3：
提出後を確認
+ 画像

これ以上の説明は原則不要。

## 3. 詳しい操作方法

操作方法が必要な人向け。

3工程をアコーディオンで確認できるようにする。

各工程も、

- 操作内容
- 必要なら補足
- デモへのリンク

程度にする。

「見るポイント」と「操作の流れ」が同じことを説明している場合は統合する。

## 4. 体験時の注意

常時表示する文章は最低限にする。

例えば、

「用意された写真と文章で試すデモです。実際の送信や保存は行いません。」

程度。

API・個人情報・要確認などの詳しい内容は、
「利用条件・注意事項」のアコーディオン内へまとめる。

## 5. 最後のCTA

ページを読んだ人がデモを開けるようにする。

Heroと同じ内容を長く説明し直さない。

短いタイトル
+
CTA

程度にする。

その下に関連デモを表示する。

# 重複チェック

特に以下を確認してください。

Heroで説明した内容を、
途中や末尾でもう一度説明していないか。

3枚の画像で説明した内容を、
直後の文章でそのまま再説明していないか。

「操作方法」と「見るポイント」で
同じ内容を言っていないか。

「体験について」と「注意事項」で
同じ注意を2回書いていないか。

最後のCTAで、
Heroと同じ説明をもう一度長く書いていないか。

---

# デザインについて

すべてのセクションを、

「小見出し + 大見出し + 本文 + カード」

という同じデザインにしないでください。

情報の役割によって見せ方を変えてください。

例えば、

- Hero → 大きく
- 3画面紹介 → 画像中心
- 操作方法 → アコーディオン
- 注意事項 → 小さく
- CTA → シンプルなカード
- 関連デモ → 一覧

のように、役割に応じて視覚的な強弱を付けてください。

## 新しいページ構成案

ここまでを報告してください。

承認後に実装します。

---

# 禁止

この段階では、

- 新しいキャッチコピーを量産しない
- 新しいセクションを増やさない
- 情報不足を文章追加で埋めない
- SaaSサイトのテンプレート構成を機械的に適用しない
- 既存要素を全部残したまま並べ替えるだけにしない

こと。

目的は、

**閲覧者が迷わず理解でき、必要なところだけ読めるページに編集すること**

です。
