# デモ・LP文言の日本語ナレッジ

AIがデモやLPの日本語を書く前に、このファイルを読む。
ここにある変更前の言い方を、別のデモでも繰り返さない。

このファイルに溜めるのは、実際に直した文である。
「自然な日本語にする」というルールだけを増やさない。

正本はこのファイル。新しい修正は「事例ログ」の末尾に足す。

- 初期事例: `driver_dash_demo` の LP 文言修正（2026-09）
- 元資料: `docs/lp_/driver_dash_lp_text_revision_knowledge.md` と `driver_dash_demo/docs/driver_dash_lp_text_revision_knowledge.md`（内容は同一）

---

## 1. 防ぎたい出力

次の4種類は出さない。

1. **日本語では通常使われない言い方**  
   画面やシステムを人のように書く。短い否定をたたみかける。現場で口にしない動詞を使う。
2. **読んでも意味が分からない文**  
   指示語だけ、主語や目的語を落とした見出し、図の上下左右がないと解けない文。
3. **かっこつけた言い回し**  
   対句、体言止め、キャッチコピー、持ち帰り口調。見出しを広告文にしない。
4. **ムダな比喩**  
   「出る」「渡る」「足す」「聞く先」「数えていない」などで、起きていることをぼかす。

優先順位は次のとおり。

1. 一度読んで状況が分かる
2. 誰が何をするのか分かる
3. 業務の流れがつながる
4. 営業担当者が、顧客の横で画面を見ながらそのまま読める
5. そのうえで短くする

短いことより、意味がすぐ分かることを優先する。

---

## 2. 書く手順

1. その画面で起きている事実を書き出す。この段階ではコピーを書かない。
2. その段落で伝えることを一つに決める。
3. 営業担当者が口で説明する文にする。専門家らしく見せる言葉を足さない。
4. 下のパターンと事例ログに照らす。
5. 直した文は、変更前・変更後・理由をこのファイルに残す。

出力前に確認する。

- 一度読んで意味が分かるか
- 誰が、何を、どうするかが残っているか
- 図や前後の画面を見なくても分かるか
- 口に出して不自然でないか
- 「何のこと？」と聞き返される名詞がないか
- システムが判断したように読まれないか
- 短い否定が続いていないか
- 比喩で別の問題を足していないか
- 見出しだけ読んでも内容が分かるか

## 3. パターン

各パターンの実例は、配車デモLPの修正から取っている。

### P01. システムや画面を人として書かない

分類: 通常使われない日本語

画面は判断しない。システムがすることを動詞で書き、判断は担当者の動詞で書く。

| 避ける | 書く |
| --- | --- |
| 画面が決める | 画面に候補を表示する |
| AIが判断する | 条件に合うものを候補として出し、担当者が確認する |
| 画面が教える | 画面に表示する |
| システムが気づく | 条件に合う項目を検出する |
| 機械任せ | 自動判断しない。確認項目として表示し、担当者が確認する |

変更前:

> 載せるか載せないかは、画面が決めません。人が決めます。

変更後:

> その荷物を候補として画面に表示し、実際に載せるかどうかは担当者が判断します。

理由: 「画面が決める」は擬人化。「人」では誰か分からない。

### P02. 「出る」「渡る」で表示や共有を書かない

分類: ムダな比喩 / 意味が分からない

「出る」は意味が広すぎる。何が、どこに、どの状態で見えるのかを書く。

変更前:

> 空車に、隣の荷物が出る

変更後:

> 帰り便に載せられそうな荷物があれば、候補として表示します。

近い言い換え:

- 荷物が出てきました → 載せられそうな荷物がある
- 候補が出る → 候補として表示する
- 隣の車には渡りません → 担当者が違うと、その情報に気づけません

### P03. 誰が何をするかを残す

分類: 意味が分からない / かっこつけた言い回し

短い見出しにするために、主語と目的語を削らない。

変更前:

> 決めるのは担当

変更後:

> 実際に配車するかどうかは担当者が判断します。

理由: キャッチコピーにすると、何を誰が判断するのかが消える。

### P04. 因果を文の中に書く

分類: 意味が分からない

名詞の羅列や、短文の連続で、つながりを読み手に補わせない。

変更前:

> ネット、FAX、電話。受けた人の手元にしかありません。
>
> 気づけないので、車は空のまま戻り、荷物は残ります。

変更後:

> 配送の依頼は、Web・FAX・電話などから入ります。受け付けた依頼は、それぞれの担当者が管理しています。そのため、別の担当者が持っている配送依頼には気づきにくくなります。

理由: 依頼の入り方、管理の分かれ方、気づけないこと、空車と荷物が残ること、の順で書く。

### P05. 図の位置に依存しない

分類: 意味が分からない

「上」「下」「隣」「向き」は、図を見ないと意味が決まらない。本文だけでも通る文にする。

変更前:

> 同じころ、すぐ下の担当に戻る向きの荷物が入ります。

変更後:

> その近くでは、別の担当者が配送依頼を受けています。

理由: 伝えたいのは位置ではなく、別の担当者が持つ荷物を、空車になった車両で運べる可能性があること。

### P06. その段落の話題を一つにする

分類: ムダな比喩 / 意味が分からない

説明の途中で、別の問題を足さない。比喩で新しい論点を開かない。

変更前:

> 空で走った距離も、運べなかった荷物も、誰も数えていません。

変更後:

> 誰かが悪いわけではありません。担当者ごとに情報が分かれているため、組み合わせられる車両と荷物を見つけにくい状態です。

理由: この節の主題は情報の分かれ方。計測していないこと、は別の問題になる。担当者が怠慢であるようにも書かない。

### P07. 見出しを宣伝文にしない

分類: かっこつけた言い回し

見出しも説明文として成立させる。対句や「持ち帰る」口調にしない。

変更前:

> 持ち帰るのは、この3点です。
>
> 人が増えると、電話が増えます。表が一つだと、聞く先が減ります。
>
> さっきの画面で起きたことは、これです。

変更後:

> 大きく変えるのは、配車そのものではありません。
>
> 担当者が増えるほど、情報確認のやり取りも増えていきます。
>
> 帰り便に載せられそうな荷物を、担当者に知らせます。

理由: 「これです」では何が起きたか分からない。対句は口頭説明にならない。見出しだけで、何の説明か分かること。

### P08. 短い否定を重ねない

分類: 通常使われない日本語 / かっこつけた言い回し

「しません」「変えません」「なくしません」「任せません」「違います」を答えの本体にしない。質問の意図に対して、1〜2文で説明する。

変更前:

> しません。候補を出すだけです。載せるかは担当が決めます。

変更後:

> いいえ。条件に合いそうな組み合わせを候補として表示します。実際に配車するかどうかは担当者が判断します。

近い言い換え:

- 変えません。見る表が一つになるだけです。 → ありません。担当の分け方はそのままに、必要な情報を一つの画面で確認できるようにする想定です。
- なくしません。入口はそのまま、あとで一つの表に並びます。 → ありません。依頼の受付方法はそのままでも、受け付けた内容を一つの一覧にまとめることができます。
- 任せません。画面に残します。見るのは人です。 → このデモでは自動判断しません。確認が必要な情報として画面に表示し、担当者が確認します。
- 会議も組織も変えません。 → 地域ごとの担当分けや、これまでの仕事の進め方を大きく変える必要はありません。

既存の仕事の進め方を否定しない。自動化できる範囲を、実装より大きく見せない。最終判断が担当者なら、その文を残す。

### P09. 操作手順ではなく、内容を書く

分類: 意味が分からない

ボタンやリンクは、押したあとに何が分かるかで名づける。

変更前:

> 下の説明を読む

変更後:

> 仕組みを見る

近い言い換え:

- 画面を見る → デモ画面に戻る
- 画面をもう一度見てから、社内に持ち帰ってください。 → 実際の画面でもう一度、流れを確認できます。

### P10. 自動で決まると読める文にしない

分類: 意味が分からない

候補の表示と、担当者の判断を分けて書く。

変更前:

> すぐ下の担当の荷物が、その車に載ります。
>
> 載せる・載せないは担当が押します。

変更後:

> 帰り便に載せられそうな荷物があれば、候補として表示します。
>
> 実際にその荷物を載せるかどうかは、これまで通り担当者が確認して判断します。

理由: 「載ります」「押します」だと、システムが割り当てたか、ボタン操作の説明になる。デモで選んだ「載せる／載せない」は、候補に対する担当者の判断である。

### P11. 現場で使う語にする

分類: 通常使われない日本語

省略した日常語で、業務の対象をぼかさない。

| 避ける | 書く |
| --- | --- |
| 人、担当 | 担当者 |
| 車 | 車両 |
| 空、空で戻る | 空車、空車で戻る |
| ネット | Web |
| 目的地 | 配送先 |
| 表 | 一覧、画面 |
| 入口 | 受付方法（Web・FAX・電話） |
| 車を出す | 車両を手配する、配送する |
| 帰り荷 | 別の依頼 |
| 心配 | 質問 |
| 仮です | 説明用の仮設定です |

変更前:

> 荷物を降ろすと、その車は現地で空になります。

変更後:

> 配送先で荷物を降ろすと、車両は空車になります。

### P12. 事実だけでなく、その結果を書く

分類: 意味が分からない

「分かれている」で止めず、そのために何が見えないかを書く。

変更前:

> 荷物の依頼は、担当ごとに分かれています。

変更後:

> 担当が違うと、使えそうな車両や荷物の情報が見えません。

ラベルも同様に、何が増えるのかを残す。

- 人が増えたとき → 担当者が増えたとき
- よくある心配 → よくある質問
- 社内で説明するとき → このデモで見てほしいこと

## 4. 事例ログ

新しい修正は、この節の末尾に足す。番号は続け、既存の番号は変えない。

共通項目:

- 分類: 第1節の4種類のいずれか（複数可）
- パターン: P01〜P12（新しい問題なら、先にパターンを足してから記録する）
- 状況: どんな説明の場面か
- 出典: デモ名、画面や節、日付
- 変更前 / 変更後 / 理由

### 001 画面を判断の主体にしない

- 分類: 通常使われない日本語
- パターン: P01, P03
- 状況: 候補の表示と、載せるかどうかの判断
- 出典: driver_dash_demo LP / ヒーロー（2026-09）

変更前:

> 載せるか載せないかは、画面が決めません。人が決めます。

変更後:

> その荷物を候補として画面に表示し、実際に載せるかどうかは担当者が判断します。

理由: 画面を判断する主体として書いていた。「人」も誰か分からない。システムの役割と担当者の役割を分けた。

### 002 「出てきました」では何が起きたか分からない

- 分類: ムダな比喩 / 意味が分からない
- パターン: P02, P05
- 状況: 空車と、別担当の荷物の関係
- 出典: driver_dash_demo LP / ヒーロー（2026-09）

変更前:

> 空で戻る車に、隣の担当が持っている荷物が出てきました。

変更後:

> 荷物を降ろして空車になった車両に、別の担当者が受けている荷物を載せられそうな場合があります。

理由: 「出てきました」は出現の比喩。「隣の担当」は位置にも読める。空車になったこと、別担当の依頼があること、載せられる可能性があることを順に書いた。

### 003 指示語だけの見出し

- 分類: 意味が分からない / かっこつけた言い回し
- パターン: P07
- 状況: 冒頭で、デモ画面が何をするかを示す
- 出典: driver_dash_demo LP / ヒーロー（2026-09）

変更前:

> さっきの画面で起きたことは、これです。

変更後:

> 帰り便に載せられそうな荷物を、担当者に知らせます。

理由: 「これです」では内容が分からない。最初の一文で、画面の役割を書く。

### 004 ボタン名が操作の説明になっている

- 分類: 意味が分からない
- パターン: P09
- 状況: 次の節へのリンク
- 出典: driver_dash_demo LP / ヒーロー（2026-09）

変更前:

> 下の説明を読む

変更後:

> 仕組みを見る

理由: 画面上の位置を説明しているだけで、次に何が分かるかが残っていなかった。

### 005 事実だけで、困ることが伝わらない

- 分類: 意味が分からない
- パターン: P12
- 状況: 現状の問題を見出しで示す
- 出典: driver_dash_demo LP / 現場（2026-09）

変更前:

> 荷物の依頼は、担当ごとに分かれています。

変更後:

> 担当が違うと、使えそうな車両や荷物の情報が見えません。

理由: 分かれ方の説明で終わっていた。その結果、何が見えないかを一文に入れた。

### 006 短文の羅列で因果が切れている

- 分類: 意味が分からない
- パターン: P04, P11
- 状況: 依頼の受付から、空車と荷物が残るまで
- 出典: driver_dash_demo LP / 現場（2026-09）

変更前:

> ネット、FAX、電話。受けた人の手元にしかありません。空で戻る車があっても、隣の担当の荷物には気づけません。気づけないので、車は空のまま戻り、荷物は残ります。

変更後:

> 配送の依頼は、Web・FAX・電話などから入ります。受け付けた依頼は、それぞれの担当者が管理しています。そのため、荷物を降ろして空車になった車両があっても、別の担当者が持っている配送依頼には気づきにくくなります。結果として、車両が空車のまま戻る一方で、運べる可能性のあった荷物が残ることがあります。

理由: 読み手が、依頼・担当・空車・荷物の関係を補う必要があった。

### 007 図を見ながら解読する文

- 分類: 意味が分からない
- パターン: P05, P02
- 状況: 空車の近くで、別担当が依頼を受けている
- 出典: driver_dash_demo LP / 埋め込み図（2026-09）

変更前:

> 同じころ、すぐ下の担当に戻る向きの荷物が入ります。いま空になった車と、進む向きが同じ荷物です。

変更後:

> その近くでは、別の担当者が配送依頼を受けています。空車になった車両で運べそうな荷物ですが、その情報は別の担当者が管理しています。

理由: 「すぐ下」「戻る向き」「進む向き」は図がないと解けない。

### 008 位置の「隣」で情報共有を書く

- 分類: 意味が分からない
- パターン: P05
- 状況: 担当が違うと組み合わせに気づけない
- 出典: driver_dash_demo LP / 埋め込み図（2026-09）

変更前:

> この荷物は、隣の担当の車には渡りません。担当ごとに依頼を持っているので、互いの空きが見えません。

変更後:

> 車両と荷物を組み合わせられる可能性があっても、担当者が違うと気づけません。それぞれが自分の依頼だけを見ているため、ほかの担当者の荷物や空車の状況が分かりません。

理由: 「渡る」「空きが見える」では、何の情報が共有されないのかが残らない。

### 009 比喩で別の問題を開く

- 分類: ムダな比喩
- パターン: P06
- 状況: 情報の分かれ方が繰り返される、という締め
- 出典: driver_dash_demo LP / 埋め込み図（2026-09）

変更前:

> 空で走った距離も、運べなかった荷物も、誰も数えていません。

変更後:

> 誰かが悪いわけではありません。担当者ごとに情報が分かれているため、組み合わせられる車両と荷物を見つけにくい状態です。

理由: 「数えていない」は計測の話になる。主題は、組み合わせに気づけないこと。

### 010 システムが割り当てたように読める

- 分類: 意味が分からない
- パターン: P10
- 状況: 導入後の流れ。候補表示のあと
- 出典: driver_dash_demo LP / 変化の説明（2026-09）

変更前:

> すぐ下の担当の荷物が、その車に載ります。空で戻る車が1台減ります。なくなるわけではありません。

変更後:

> 帰り便に載せられそうな荷物があれば、候補として表示します。候補を確認し、実際に載せるかどうかは担当者が判断します。

理由: 自動で積む説明になっていた。短い否定の対句も、口頭の説明にならない。前提は「候補を表示し、担当者が判断する」。

### 011 ボタン操作と業務判断が混ざる

- 分類: 通常使われない日本語
- パターン: P10, P03
- 状況: 何が変わり、何が残るか
- 出典: driver_dash_demo LP / 変化の説明（2026-09）

変更前:

> 依頼は入った時点で、一つの表に並びます。担当は今まで通り分かれています。会議も組織も変えません。空になった車に、隣の荷物が候補として出ます。載せる・載せないは担当が押します。休息の確認と、FAXの読み取り漏れは消しません。

変更後:

> Web・FAX・電話で受けた依頼を、一つの一覧で確認できるようにします。地域ごとの担当分けや、これまでの仕事の進め方を大きく変える必要はありません。車両が空車になったときは、近くに運べそうな荷物があれば候補として表示します。実際にその荷物を載せるかどうかは、これまで通り担当者が確認して判断します。

理由: 「出ます」「押します」「消しません」が続き、処理の中身が分からない。強い否定のリズムも、テンプレート文に聞こえる。

### 012 対句の見出し

- 分類: かっこつけた言い回し
- パターン: P07, P04
- 状況: 人数が増えたときの確認作業
- 出典: driver_dash_demo LP / 担当者が増えたとき（2026-09）

変更前:

> 人が増えると、電話が増えます。表が一つだと、聞く先が減ります。今は5人です。隣が何を持っているかは、聞かなければ分かりません。仕事が増えると人を足します。足すほど、確認の電話が増えます。同じ表を見ていれば、聞く先はその表だけです。担当は増えても構いません。増え方がきついのは、確認の手間のほうです。

変更後:

> 担当者が増えるほど、情報確認のやり取りも増えていきます。担当者が少ないうちは、電話や声かけでも情報を確認できます。しかし、配送件数が増えて担当者も増えると、「どの荷物を持っているか」「空いている車両はあるか」といった確認の回数も増えていきます。全員が同じ一覧を見られれば、毎回ほかの担当者に確認しなくても、必要な情報を自分で確認できます。

理由: 「人を足す」「聞く先」「増え方がきつい」は口語の比喩で、何の確認が増えるのかが残らない。
